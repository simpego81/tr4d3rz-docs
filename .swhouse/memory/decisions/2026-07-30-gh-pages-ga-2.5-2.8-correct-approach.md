## Context

The GitHub Pages landing page (`docs/index.html`) contains a scroll-driven 2nd Concept narrative that explains the Genetic Algorithm used by TR4D3RZ. Phases 2.1–2.4 establish: an OHLCV canvas, an ALU SVG, a Three.js state machine, a genome/CAGR table with individuals stacked in a portfolio. Phase 2.5 (Selection) must continue from this established state. Previous implementation introduced disconnected overlays and colored genome blocks, which the owner rejected.

## Decision

**D1 — Single table, no replacement**
Phases 2.5–2.8 operate on the SAME `<table>` element that is already visible in phase 2.3. There is no separate `#ga-sel`, `#ga-xover`, or `#ga-mut` overlay element. The table transitions in-place: it expands to full-viewport width/height, populates ~20 rows sorted by CAGR descending, and subsequent phases mutate visible rows of that same table.

**D2 — No colored genome blocks**
Genome cells display their raw text values (e.g., IIR1_P, ls_axiom values) in the same plain styling as phases 2.1–2.4. No color-coded block strips. Highlighting (for selection, crossover field choice, mutation) is expressed via a single `background-color` highlight class applied temporarily to individual cells — never a structural re-render.

**D3 — Phase-by-phase DOM transformations**
- 2.5 Selection: table expands full-screen; ~20 rows appear sorted by CAGR desc; two animated arrows (`position: absolute`) move toward two parent rows; non-parent rows fade out; parent rows scale up (1.25×); CAGR column fades.
- 2.6 Crossover: the two parent rows remain visible; individual genome cells highlight alternately between Parent A and Parent B; highlighted cells merge downward into a new "Child" row appended at the bottom.
- 2.7 Mutation: all rows except the Child row fade; one random genome cell in the Child row highlights and its value ticks to a nearby number (the mutation).
- 2.8 Birth: the Child row animates out and re-enters the stack in the portfolio, with a border flash on the individual card.

**D4 — GSAP + ScrollTrigger for all transitions**
Use the same GSAP 3.12.2 + ScrollTrigger already loaded for 2.1–2.4. No new libraries. Pin the `#ga-stage` section and use `scrub: true` timelines where possible.

## Rationale

The spec (STAKEHOLDER_PAGE_SPECIFICATION.md) is unambiguous: "la tabella prende tutta la visuale" means the existing table expands. Visual narrative continuity requires the viewer to recognize the same table they saw in 2.3 — a new element breaks the cognitive thread and undermines the storytelling effect. No coloring was specified and plain genome text is more legible for a technical stakeholder audience.

## Consequences

- The previous `#ga-sel`, `#ga-xover`, `#ga-mut` elements must be removed from `docs/index.html`
- JS initialization code for those overlays must be deleted
- The table rendered in 2.3 must be given a stable `id` (e.g., `#ga-table`) and made accessible to the 2.5–2.8 scroll trigger handlers
- ~20 genome rows must be pre-generated in JS at init time and initially hidden; revealed in phase 2.5

## Confidence

High. Decision is fully grounded in owner feedback and verbatim spec language.
